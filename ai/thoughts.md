Some AI coding impressions (long feel free to ignore):

1. The AI still takes time to write code, and there is back and forth due to developer or AI mistakes, so it is hard for even a developer to judge how much time savings there is or will be. The "mythical man-month" problem remains. I am writing much higher quality code, but am I doing it faster? Hard to tell.
2. It takes about same amount of time to ask AI to change one line as it takes to refactor entire files. Large edits/refactors become reasonable in a single story.
3. Even when changing only one line, there is often other files that need updating and documentation. AI can do it all at once with a good prompt.
4. DX is still improving. Agent mode needs to be able to delegate to background and notify when done. Agent mode needs more automatic sandboxing. It often wants to run crazy long custom scripts which no human could verify in a reasonable time as "secure". It should run these in a docker container for security/safety.
5. There are no longer "lack of documentation" or "code obfuscation" or "too difficult to figure out in allotted time" blockers. If the code is possible, it can be written even if its not known how to do it ahead of time.
6. The AI is still on occasion, rarely, wrong. It makes mistakes but now more so because of miscommunication/misunderstanding and less because it got something wrong.
7. After a series of small changes, the AI isn't good at noticing new emerging larger patterns. Perhaps in the future it will notice/suggest these patterns, but for now entirely on human to keep track of the "forest" (vs the individual "trees").
8. Dynamic & weak type systems result in significantly more PR comments generated by the AI versus strongly static typed languages, e.g. Azure pipeline templates (20+ comments per PR) -> python (~10 comments per PR) -> scala (~2 comments per PR). Even for gen AI code. I expect that over time developers will start to prefer strongly typed languages (Scala, Haskell, Rust? etc) since AI generated code can be trusted more and less review is needed. How difficult code is to write much less important than how easy it is to read.
9. The most important developer skills: 1) "Grokking" code quickly with an increasing ability to spot patterns of failure in generated code. 2) time management to avoid chasing "perfect" code which becomes reasonable with gen AI 3) awareness around new ideas/patterns for working with the AI (we are just getting started with this -- next 10 years will be interesting).
10. I am skeptical still of fully automated coding systems since the "what do I really want" problem remains. The full specification of code, is the code. Any request with less precision has "common sense" gaps that the AI is guessing at. "Plan mode" helps prevent this issue. But then the plan becomes the new "what do I really want".
11. I do think fully automated upgrades for simple & medium changes are reasonable. Fully automated bug triage is reasonable. Fully automated bug fixes (based on those triages) for most bugs is probably reasonable too. Bug fixing and upgrades narrow the "what do I really want" problem into a tight goal space. Though I think all code should still be reviewed by at least one human developer always.
